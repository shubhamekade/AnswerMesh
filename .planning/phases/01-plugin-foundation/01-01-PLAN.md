# Plan 01-01: Plugin Bootstrap & Database Schema

**Phase:** 1 — Plugin Foundation & Core Architecture  
**Plan ID:** 01-01  
**Type:** Tracer Slice  
**Requirements Addressed:** REQ-F01, REQ-F02, NFR-01, NFR-03  
**Status:** Planned  

---

## 1. Objective
Establish the primary WordPress plugin entrypoint, PSR-4-compatible autoloader / includes structure, plugin singleton container, activation lifecycle hooks, and custom database schema creation for the 5 analytics tables using `dbDelta()`.

---

## 2. Context & Design Decisions
- **Entrypoint:** `answermesh.php` declaring standard WordPress plugin header comments, strict PHP 8.1+ requirement check, and defining core constants (`ANSWERMESH_VERSION`, `ANSWERMESH_FILE`, `ANSWERMESH_DIR`, `ANSWERMESH_URL`).
- **Container / Orchestrator:** `includes/class-plugin.php` serving as the dependency coordinator registering WordPress actions (`plugins_loaded`, `init`, `admin_menu`, `rest_api_init`).
- **Database Tables:** Custom migration runner `includes/class-database.php` executing `dbDelta()` on activation to construct:
  1. `{$wpdb->prefix}aiseo_scores`
  2. `{$wpdb->prefix}aiseo_entities`
  3. `{$wpdb->prefix}aiseo_questions`
  4. `{$wpdb->prefix}aiseo_recommendations`
  5. `{$wpdb->prefix}aiseo_visibility`
- **Data Cleanup:** `uninstall.php` checking the `answermesh_delete_data_on_uninstall` option before pruning tables or options.

---

## 3. Detailed Tasks

### Task 1: Create Main Plugin Bootstrap File
- Create `answermesh.php` with:
  - Header: Plugin Name ("AnswerMesh"), Plugin URI, Description, Version ("1.0.0"), Author, Author URI, License ("GPL-2.0+"), Requires at least ("6.0"), Requires PHP ("8.1").
  - `defined('ABSPATH') || exit;` guard.
  - PHP version compatibility guard throwing an admin notice if running on PHP < 8.1.
  - Constants definition: `ANSWERMESH_VERSION`, `ANSWERMESH_FILE`, `ANSWERMESH_DIR`, `ANSWERMESH_URL`, `ANSWERMESH_DB_VERSION`.
  - Autoload / includes inclusion.
  - Hook `register_activation_hook` and `register_deactivation_hook`.

### Task 2: Implement Dependency Container & Core Lifecycle
- Create `includes/class-plugin.php`:
  - Singleton pattern `Plugin::get_instance()`.
  - Properties holding references to subsystems (database, settings, rest_api).
  - Initialization method `init()` hooked to `plugins_loaded`.
  - Core hook bindings.

### Task 3: Implement Database Schema & Migration Runner
- Create `includes/class-database.php`:
  - Constant `DB_VERSION = '1.0.0'`.
  - Method `create_tables()`:
    - Include `ABSPATH . 'wp-admin/includes/upgrade.php'`.
    - Define SQL statements with proper column types, indexes, and primary keys for:
      - `aiseo_scores`: `id bigint(20) unsigned NOT NULL AUTO_INCREMENT`, `post_id bigint(20) unsigned DEFAULT 0`, `seo_score tinyint(3) unsigned NOT NULL DEFAULT 0`, `aeo_score tinyint(3) unsigned NOT NULL DEFAULT 0`, `geo_score tinyint(3) unsigned NOT NULL DEFAULT 0`, `entity_score tinyint(3) unsigned NOT NULL DEFAULT 0`, `trust_score tinyint(3) unsigned NOT NULL DEFAULT 0`, `overall_score tinyint(3) unsigned NOT NULL DEFAULT 0`, `created_at datetime NOT NULL`, `updated_at datetime NOT NULL`, `PRIMARY KEY  (id)`, `KEY post_id (post_id)`.
      - `aiseo_entities`: `id bigint(20) unsigned NOT NULL AUTO_INCREMENT`, `type varchar(64) NOT NULL`, `name varchar(255) NOT NULL`, `description text`, `url varchar(500) DEFAULT ''`, `schema_type varchar(64) NOT NULL`, `data_json longtext`, `created_at datetime NOT NULL`, `updated_at datetime NOT NULL`, `PRIMARY KEY  (id)`, `KEY type (type)`.
      - `aiseo_questions`: `id bigint(20) unsigned NOT NULL AUTO_INCREMENT`, `question text NOT NULL`, `intent varchar(32) NOT NULL DEFAULT 'informational'`, `topic varchar(128) DEFAULT ''`, `post_id bigint(20) unsigned DEFAULT 0`, `status varchar(32) NOT NULL DEFAULT 'missing'`, `confidence varchar(16) NOT NULL DEFAULT 'medium'`, `created_at datetime NOT NULL`, `PRIMARY KEY  (id)`, `KEY post_id (post_id)`, `KEY status (status)`.
      - `aiseo_recommendations`: `id bigint(20) unsigned NOT NULL AUTO_INCREMENT`, `post_id bigint(20) unsigned DEFAULT 0`, `type varchar(64) NOT NULL`, `priority varchar(16) NOT NULL DEFAULT 'medium'`, `title varchar(255) NOT NULL`, `description text`, `evidence text`, `confidence varchar(16) NOT NULL DEFAULT 'medium'`, `status varchar(32) NOT NULL DEFAULT 'pending'`, `created_at datetime NOT NULL`, `updated_at datetime NOT NULL`, `PRIMARY KEY  (id)`, `KEY post_id (post_id)`, `KEY priority (priority)`, `KEY status (status)`.
      - `aiseo_visibility`: `id bigint(20) unsigned NOT NULL AUTO_INCREMENT`, `query varchar(255) NOT NULL`, `platform varchar(64) NOT NULL`, `observed tinyint(1) NOT NULL DEFAULT 0`, `mention tinyint(1) NOT NULL DEFAULT 0`, `position_context text`, `source_url varchar(500) DEFAULT ''`, `competitors_json longtext`, `captured_at datetime NOT NULL`, `PRIMARY KEY  (id)`, `KEY query (query(191))`, `KEY platform (platform)`.
    - Run `dbDelta($sql)`.
    - Update `answermesh_db_version` in `wp_options`.
  - Method `check_version()` for automatic upgrade execution.

### Task 4: Implement Installer & Uninstall Handler
- Create `includes/class-installer.php` handling `activate()` and `deactivate()`.
- Create `uninstall.php`:
  - Security check: `defined('WP_UNINSTALL_PLUGIN') || exit;`.
  - Check option `answermesh_delete_data_on_uninstall`.
  - If true, drop tables `aiseo_*` and clean up `answermesh_*` options.

---

## 4. Verification & Acceptance Criteria
- [ ] `answermesh.php` passes `php -l` without errors.
- [ ] `includes/class-plugin.php`, `includes/class-database.php`, `includes/class-installer.php` pass `php -l` without errors.
- [ ] SQL schema syntax valid for MySQL 8+ / MariaDB and conforms to WordPress `dbDelta()` formatting rules (two spaces after PRIMARY KEY, lowercase types, uppercase keywords).
- [ ] Lifecycle hooks properly bound to activation/deactivation/uninstall.
