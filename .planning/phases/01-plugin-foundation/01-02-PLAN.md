# Plan 01-02: Settings & Security Subsystem

**Phase:** 1 — Plugin Foundation & Core Architecture  
**Plan ID:** 01-02  
**Type:** Core Feature Subsystem  
**Requirements Addressed:** REQ-F03, REQ-F05, NFR-01, NFR-04  
**Status:** Planned  

---

## 1. Objective
Implement the centralized Settings API manager, secure symmetric credential encryption for AI API keys, administrative menu routing, and privacy/telemetry preference controls.

---

## 2. Context & Design Decisions
- **Settings Store:** Stored in `wp_options` under partitioned keys `answermesh_settings` to keep database reads minimal (single autoloaded row for general options).
- **Credential Protection:** API keys must **never** be stored in plaintext in the database or exposed via API / client JavaScript. `includes/class-encryption.php` will perform symmetric encryption using OpenSSL (`aes-256-cbc`) with keys derived from WordPress `AUTH_KEY` and `SECURE_AUTH_SALT`.
- **Admin Menu Routing:** Main menu entry "AnswerMesh" (`toplevel_page_answermesh`) using an SVG or Dashicon (`dashicons-networking`), with submenus for Dashboard, Business Knowledge, Pages, and Settings.
- **Sanitization & Permissions:** Strict capability enforcement requiring `manage_options` for settings modification and secure nonce verification.

---

## 3. Detailed Tasks

### Task 1: Symmetric Encryption Utility
- Create `includes/class-encryption.php`:
  - Method `encrypt(string $plaintext): string` using OpenSSL AES-256-CBC, IV generation via `random_bytes(16)`, base64 encoding IV + ciphertext.
  - Method `decrypt(string $ciphertext): string` with validation and fallback.
  - Key derivation based on `defined('AUTH_KEY') ? AUTH_KEY : ...` combined with `LOGGED_IN_SALT`.
  - Unit-testable structure.

### Task 2: Settings Management Controller
- Create `includes/class-settings.php`:
  - Static defaults covering:
    - `general`: `enable_plugin` (true), `enable_analysis` (true), `enable_schema` (true), `enable_sitemap` (true), `delete_data_on_uninstall` (false).
    - `ai`: `provider` ('none'), `api_key` (''), `model` ('gpt-4o-mini'), `language` ('en'), `temperature` (0.3), `max_tokens` (1500).
    - `seo`: `title_separator` ('-'), `default_robots` ('index, follow'), `canonical_enabled` (true).
    - `schema`: `site_type` ('Organization'), `business_name` (''), `logo_url` (''), `social_profiles` ([]).
    - `brand_voice`: `tone` ('professional'), `custom_instructions` (''), `target_audience` ('').
    - `privacy`: `allow_ai_processing` (false by default until opted in), `allow_telemetry` (false).
  - Methods: `get(string $group, string $key = null, $default = null)`, `set(string $group, array $values)`, `save()`.
  - Automatic transparent encryption when writing `ai.api_key` and masked representation (`••••••••sk-1234`) when returning values for UI display.
  - Strict sanitization callbacks per setting type.

### Task 3: Admin Menu & Pages Handler
- Create `admin/class-admin-menu.php`:
  - Hook into `admin_menu`.
  - Add top-level menu page:
    - Page Title: "AnswerMesh — AI Search Visibility"
    - Menu Title: "AnswerMesh"
    - Capability: `manage_options`
    - Slug: `answermesh`
    - Render Callback: `render_app_container()` (mounting point for React app)
    - Icon: `dashicons-networking`
  - Add submenus:
    - Dashboard (`answermesh`)
    - Business Knowledge (`answermesh-knowledge`)
    - Page Analysis (`answermesh-pages`)
    - Settings (`answermesh-settings`)
  - Admin assets enqueuing restricted only to AnswerMesh screens (`strpos($hook, 'answermesh') !== false`).

## 4. Verification & Acceptance Criteria
- [ ] `class-encryption.php` successfully encrypts and decrypts strings round-trip without data corruption.
- [ ] Decrypted API key matches original input; database stores encrypted ciphertext.
- [ ] Settings controller loads defaults when no options exist.
- [ ] Masked API key representation returned for client queries; full key never sent to unauthenticated or client scripts.
- [ ] Admin menu displays correctly under `admin_menu` hook with capability check `manage_options`.
- [ ] PHP syntax check `php -l` passes on all created files.
