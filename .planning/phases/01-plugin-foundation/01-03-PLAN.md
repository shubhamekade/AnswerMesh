# Plan 01-03: REST API Foundation & Asset Pipeline

**Phase:** 1 — Plugin Foundation & Core Architecture  
**Plan ID:** 01-03  
**Type:** Integration & Infrastructure  
**Requirements Addressed:** REQ-F04, NFR-01, NFR-02  
**Status:** Planned  

---

## 1. Objective
Establish the secured WordPress REST API base controller under namespace `/wp-json/aiseo/v1/` and scaffold the modern React admin asset pipeline using `@wordpress/scripts` for dashboard and future Gutenberg integrations.

---

## 2. Context & Design Decisions
- **REST Namespace:** `aiseo/v1` as defined in PRD Section 52.
- **Permission Callbacks:** Explicit, non-bypassable permission callbacks on every route using `current_user_can('manage_options')` or `current_user_can('edit_posts')`.
- **JSON Envelope Standards:** Consistent response shape: `{ success: true, data: ... }` and standard `WP_Error` structures for failures.
- **Frontend Build Tool:** Standard `@wordpress/scripts` ensuring seamless zero-config compilation of React JSX, Gutenberg components, CSS extraction, and automatic dependency manifest creation (`build/index.asset.php`).

---

## 3. Detailed Tasks

### Task 1: REST API Base Controller & Endpoints
- Create `includes/class-rest-api.php`:
  - Hook to `rest_api_init`.
  - Namespace constant: `NAMESPACE = 'aiseo/v1'`.
  - Endpoints:
    1. `GET /aiseo/v1/status`: Returns system health, database version, active table status, active AI provider, and WordPress/PHP environment info. Permission: `manage_options`.
    2. `GET /aiseo/v1/settings`: Returns sanitized settings with masked API keys. Permission: `manage_options`.
    3. `POST /aiseo/v1/settings`: Updates settings with schema validation. Permission: `manage_options`.
    4. `GET /aiseo/v1/dashboard`: Returns initial summary skeleton (site-level scores, issue counts, recommendation totals). Permission: `manage_options`.
  - Standardized helper methods `success_response(array $data, int $status = 200)` and `error_response(string $code, string $message, int $status = 400)`.

### Task 2: Scaffold Asset Build Environment
- Create `package.json`:
  - Package name: `answermesh`.
  - DevDependencies: `@wordpress/scripts`.
  - Dependencies: `@wordpress/element`, `@wordpress/components`, `@wordpress/api-fetch`, `@wordpress/i18n`.
  - Scripts: `"build": "wp-scripts build src/index.js --output-path=build"`, `"start": "wp-scripts start src/index.js --output-path=build"`.
- Create `.gitignore`:
  - Ignore `node_modules/`, `build/`, `.planning/scratch/`, `npm-debug.log`.

### Task 3: Admin React Mounting Shell & Asset Loader
- Create `src/index.js`:
  - Basic React root mount onto DOM element `document.getElementById('answermesh-admin-root')`.
  - Placeholder shell displaying AnswerMesh app header, loading state, and status ping.
- Create `admin/class-admin-assets.php`:
  - Hook into `admin_enqueue_scripts`.
  - Verify admin hook matches `answermesh`.
  - Check for compiled manifest `build/index.asset.php`.
  - Enqueue script and styles with dependencies, version, and localized `answermeshSettings` object containing `rootUrl`, `nonce` (`wp_create_nonce('wp_rest')`), and current screen.
