# Plan 05-01: AI Provider Interface & Factory

**Phase:** 5 — AI Intelligence Services & Provider Abstraction  
**Plan ID:** 05-01  
**Type:** Tracer Slice  
**Requirements Addressed:** REQ-F18, REQ-F22, NFR-01, NFR-04  
**Status:** Planned  

---

## 1. Objective
Establish the AI provider contract `AIProviderInterface` and the central AI service manager `AI` handling provider instantiation, API key decryption, and offline/fallback detection.

---

## 2. Context & Design Decisions
- **Interface Contract:**
  - `generate(string $prompt, array $options = []): array{success: bool, content: string, error?: string}`
  - `analyze(string $text, array $context = []): array{success: bool, result: array, error?: string}`
  - `test_connection(): array{success: bool, message: string}`
- **Provider Registry:**
  - `none`: returns offline notice, disables generation without fatal errors.
  - `openai`: OpenAI GPT-4o / GPT-4o-mini.
  - `gemini`: Google Gemini 1.5 / 2.0 Flash / Pro.
  - `anthropic`: Claude 3.5 Sonnet (stub/ready).
  - `openrouter`: OpenRouter multi-model.
- **Safety & Privacy:**
  - Verify `allow_ai_processing` setting before dispatching external HTTP requests.
  - Encrypted keys decrypted solely in memory right before dispatch.

---

## 3. Detailed Tasks

### Task 1: AI Provider Interface
- Create `includes/class-ai-provider-interface.php`:
  - Definition of `AIProviderInterface`.

### Task 2: AI Manager & Factory
- Create `includes/class-ai.php`:
  - Method `get_active_provider(): ?AIProviderInterface`
  - Method `is_ai_enabled(): bool`
  - Method `test_active_connection(): array`
  - Error handling wrapping `wp_remote_post` timeouts with graceful failure envelopes.
