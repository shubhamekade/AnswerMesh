# Plan 05-02: OpenAI & Google Gemini Adapters

**Phase:** 5 — AI Intelligence Services & Provider Abstraction  
**Plan ID:** 05-02  
**Type:** Core Feature Subsystem  
**Requirements Addressed:** REQ-F19, NFR-01, NFR-02  
**Status:** Planned  

---

## 1. Objective
Implement production-ready adapters for OpenAI (using `/v1/chat/completions`) and Google Gemini (using `/v1beta/models/{model}:generateContent`) using WordPress HTTP API (`wp_remote_post`).

---

## 2. Context & Design Decisions
- **HTTP Transport:** Pure WordPress `wp_remote_post` (no external Composer Guzzle dependencies) with configurable timeout (30s) and error trapping.
- **OpenAI Adapter:**
  - Endpoint: `https://api.openai.com/v1/chat/completions`.
  - Default model: `gpt-4o-mini`.
  - Bearer token authentication in headers.
- **Gemini Adapter:**
  - Endpoint: `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent?key={api_key}`.
  - Default model: `gemini-1.5-flash` or `gemini-2.0-flash`.
  - Request payload structure: `{ contents: [{ parts: [{ text: prompt }] }] }`.

---

## 3. Detailed Tasks

### Task 1: OpenAI Adapter
- Create `includes/class-ai-openai.php`:
  - Implements `AIProviderInterface`.
  - Methods: `generate()`, `analyze()`, `test_connection()`.
  - Error parsing for quota, invalid key, rate limits.

### Task 2: Google Gemini Adapter
- Create `includes/class-ai-gemini.php`:
  - Implements `AIProviderInterface`.
  - Methods: `generate()`, `analyze()`, `test_connection()`.
  - Payload translation and response unpacking.

---

## 4. Verification & Acceptance Criteria
- [ ] Both adapters implement `AIProviderInterface` completely.
- [ ] Network errors and invalid JSON responses handled gracefully without throwing fatal exceptions.
- [ ] `php -l` passes on both files.
