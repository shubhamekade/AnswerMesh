# Plan 10-01: Visibility Data Model, Storage Manager & REST Endpoints

**Phase:** 10 — Observed AI Search Visibility Engine  
**Plan ID:** 10-01  
**Type:** Backend Data Architecture Slice  
**Requirements Addressed:** REQ-M3-01, NFR-M3-03  
**Status:** Planned  

---

## 1. Objective
Create `AnswerMesh\Visibility` (`includes/class-visibility.php`) as the dedicated data model and query manager for `wp_aiseo_visibility`. Support recording observations, querying historical records by platform or date range, computing aggregate metrics (citation rate, mention rate), and automatic pruning of records older than 90 days. Register REST API routes for visibility data retrieval and query configuration.

---

## 2. Context & Design Decisions
- **Table Structure:**
  - Table: `{$wpdb->prefix}aiseo_visibility`
  - Columns: `id`, `query`, `platform` (`chatgpt`, `gemini`, `perplexity`, `copilot`), `observed`, `mention`, `position_context`, `source_url`, `competitors_json`, `captured_at`.
- **Core Operations:**
  - `record_observation(array $data): int|false`: Inserts observation with sanitized fields and JSON encoding of competitors.
  - `get_observations(array $args): array`: Fetches logs filtered by `platform`, `query`, `from_date`, `to_date`, `limit`, `offset`.
  - `get_summary(int $days = 30): array`: Computes total queries, total observed, citation rate %, mention rate %, and platform breakdown.
  - `prune_old_records(int $days = 90): int`: Deletes records older than `$days` to satisfy NFR-M3-03.
- **REST Endpoints (`includes/class-rest-api.php`):**
  - `GET /aiseo/v1/visibility/summary`: Returns aggregate metrics (rates, platform share, total checks).
  - `GET /aiseo/v1/visibility/observations`: Lists paginated observation records with search and platform filters.
  - `DELETE /aiseo/v1/visibility/prune`: Manually triggers 90-day retention pruning.

---

## 3. Detailed Tasks
1. Create `includes/class-visibility.php` (`AnswerMesh\Visibility`) with CRUD, query aggregations, and pruning.
2. Register `/visibility/summary`, `/visibility/observations`, and `/visibility/prune` routes in `includes/class-rest-api.php`.
3. Add unit test suite in `tests/test-visibility.php` testing insertion, querying, summary calculation, and pruning.

---

## 4. Verification & Acceptance Criteria
- [ ] Observations properly inserted and retrieved with prepared SQL statements.
- [ ] `get_summary()` calculates accurate citation and mention percentages across all platforms.
- [ ] Pruning routine removes records older than specified threshold.
- [ ] REST API endpoints return properly formatted JSON payloads with permission verification.
